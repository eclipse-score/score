Assumptions of Use#

Vehicle Time Integration#

Vehicle time value integrity
status: valid
security: NO
safety: ASIL_B
reqtype: Non-Functional
version: 1

The integrity of the vehicle time value is not guaranteed by score::time alone. If the system using score::time has the safety goal to treat the vehicle time as ASIL-B data, the system integrator shall establish end-to-end integrity by suitable measures, e.g.:

  • integrity protection along the time-distribution chain (grand master, intermediate masters, time-aware bridges/switches), and/or

  • a receiver-side qualification/monitoring mechanism that evaluates the qualifiers provided by score::time (see Vehicle Time base time poin... (feat_req__time__vehicle_time_time_pt_qual)) and reacts per the project safety concept.

Note 1: score::time provides the qualifier/detection hooks; the concrete integrity mechanism, its redundancy, the safety reaction and the end-to-end safety argument are project-specific and outside the scope of the score::time SEooC.

Note 2: If this assumption is not fulfilled, the vehicle time value integrity falls back to QM and must be marked accordingly in the project documentation.

Scheduling configuration of score::time
status: valid
security: NO
safety: ASIL_B
reqtype: Non-Functional
version: 1

The system integrator shall configure the scheduling of score::time and provide CPU time so that the time synchronization data and the Vehicle Time status reach their consumers within the time budget derived from the fault tolerant time interval of the consuming functions.

Note: the scheduling configuration covers e.g. the priorities, the core assignment and the CPU time budget of the processes of score::time.

Vehicle Time Usage#

A Vehicle Time Snapshot carries two independent pieces of information about its TimePoint: the Vehicle Time status tells whether the TimePoint is meaningful, and the time point qualifier tells whether the TimePoint may be treated as ASIL-B data. The following assumptions describe how the user combines both.

Elapsed time measurement
status: valid
security: NO
safety: ASIL_B
reqtype: Non-Functional
version: 1

The user shall measure elapsed time within one ECU with the Steady Clock.

Note: the Vehicle Time is not monotonic; a time synchronization update may decrease it.
aou_req__feature_time__elapsed_time_clock
Assumption of Use Requirement
Vehicle Time status evaluation
status: valid
security: NO
safety: ASIL_B
reqtype: Non-Functional
version: 1

The user shall use a TimePoint only if the Vehicle Time status of the same Snapshot fulfils the requirements of the user’s use case.
aou_req__feature_time__veh_status_eval
Assumption of Use Requirement
Vehicle Time time point qualifier evaluation
status: valid
security: NO
safety: ASIL_B
reqtype: Non-Functional
version: 1

The user shall treat a TimePoint as ASIL-B data only if the time point qualifier of the same Snapshot indicates ASIL-B data.
aou_req__feature_time__veh_tpq_eval

Absolute Time Integration#

Absolute Time qualifier evaluation
status: valid
security: YES
safety: QM
reqtype: Non-Functional
version: 1

The user shall use an Absolute Time TimePoint only if the accuracy qualifier and the security qualifier of the same Snapshot fulfil the requirements of the user’s use case.

Note: the security qualifier depends on external conditions, e.g. the connectivity to a secure time source.
